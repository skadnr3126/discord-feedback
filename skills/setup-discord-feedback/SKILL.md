# Discord 원격 피드백 환경 설정

이 스킬은 사용자가 선택한 프로젝트에 실행 환경을 실제로 준비한다. 설명만 요청하면 설명하고, 설정 요청이면 준비된 작업부터 끝까지 진행한다. 단계마다 별도 승인을 요구하지 않는다. 설치만으로 환경이 완료됐다고 보고하지 않는다.

## 입력과 완료 기준

현재 대화·작업 디렉터리·기존 설정에서 프로젝트 경로, Discord 채널 ID, 허용 사용자 범위를 확인한다. 이미 주어진 내용을 다시 묻지 않는다. 사용자 범위는 지정 채널 접근자 전체(`all`) 또는 쉼표로 구분한 사용자 ID다. 다른 프로젝트의 채널·사용자 권한을 임의로 재사용하지 않는다. 필수 정보가 없으면 한 번에 묻고 독립적인 환경 조사는 계속한다.

Discord 토큰은 런타임의 `DISCORD_BOT_TOKEN` 환경변수로 준비한다. 토큰을 채팅으로 요청하거나 출력하지 않는다. `DISCORD_CHANNEL_ID`가 준비돼 있으면 활용한다. 인증 파일·토큰·대화·로그를 플러그인 소스나 배포물에 넣지 않는다.

완료 기준은 의존 플러그인 설치와 활성화, 실제 Codex 스킬 읽기, 선택 프로젝트의 서비스 RUNNING 및 Discord Gateway READY다. 실제 사용자 메시지 수신·답장을 확인한 경우와 연결 상태만 확인한 경우를 구분해 보고한다.

## 환경 확인

이 파일 기준 `../../scripts/manage.py`를 설치·진단·제어의 유일한 진입점으로 사용한다. `<plugin-root>`는 현재 읽은 설치본의 실제 경로로 치환한다. 소스 저장소 경로나 설치 캐시 이름을 하드코딩하지 않는다. 상세 설정은 [클라우드 설정](../../references/cloud-setup.md)을 읽는다.

관리형 클라우드에서 `cloud_environment.environment_status` 도구가 제공되면 환경 상태·변수 준비·적용된 정책을 확인한다. 도구가 없으면 관리 스크립트의 검사 결과를 사용하고 플랫폼 상태는 미확인으로 남긴다. 제한 네트워크의 허용 호스트 변경은 플랫폼의 지원되는 설정 절차를 사용한다. `/etc/codex/network-policy.json` 편집, 프록시 우회, TLS 검증 해제로 접근을 시도하지 않는다. 기존 프록시·CA·플랫폼 인증 환경변수는 보존한다.

첫 버전은 Linux/Unix, Node 24.5 이상, Python 3.10 이상과 pip, Git, 플러그인 기능을 지원하는 Codex CLI를 사용한다. 설치본은 실행 자산을 포함하고 별도 상태 폴더에 실행 버전을 배치한다. 상태·인증·로그를 설치 캐시에 쓰지 않는다.

실행자의 파일 샌드박스가 선택 프로젝트만 쓰도록 제한하면 상태 폴더에 대한 쓰기를 해당 도구의 지원되는 권한 절차로 허용한다. 상태 경로와 설치·패키지 실행에 필요한 범위만 요청한다. 전체 샌드박스를 우회하는 플래그를 기본 설정으로 추가하지 않는다. 사용자가 이미 승인한 환경 설정 범위의 권한을 다시 묻지 않는다.

## 설치와 로그인

사용자 범위가 채널 접근자 전체로 정해진 경우의 예시다. ID 제한이면 `all` 대신 확인한 ID 목록을 넣는다.

```bash
python3 "<plugin-root>/scripts/manage.py" setup \
  --project "<project-path>" --channel "<channel-id>" \
  --allowed-users all
```

스크립트는 프로젝트별 설정, 원격 기본 브랜치의 최신 남욱 프로세스 버전, Node 의존성, Supervisor를 준비한다. 설치를 다시 실행하면 같은 프로필에서 남욱 프로세스를 최신 커밋으로 갱신한다. 종료 코드 2는 준비한 설정을 보존한 채 로그인 또는 필수 변수가 아직 필요하다는 뜻이다. JSON의 `checks`를 보고 해결한다.

기존 봇 전용 인증 경로를 사용하도록 사용자가 지정한 경우에만 `--codex-home "<existing-bot-home>"`을 추가한다. 주입된 클라우드 인증 파일을 복사하거나 덮어쓰지 않는다. 기본은 별도 봇 전용 Codex 홈이다.

로그인이 필요하면 다음 명령을 실행하고 CLI가 발급한 인증 링크·일회용 코드를 사용자에게 안내한다. 사용자 계정 인증은 대신 수행할 수 없으므로 기다리면서 독립 작업은 계속한다. 성공을 실제 명령 결과로 확인한다. 디바이스 코드가 만료되면 새 로그인 절차를 시작한다.

```bash
python3 "<plugin-root>/scripts/manage.py" login --project "<project-path>"
```

Bot의 Message Content Intent와 대상 채널의 View Channel/Send Messages 권한을 확인한다. 서버 관리자 권한은 필요하지 않다.

## 실행과 검증

```bash
python3 "<plugin-root>/scripts/manage.py" start --project "<project-path>"
python3 "<plugin-root>/scripts/manage.py" doctor --project "<project-path>" --probe
python3 "<plugin-root>/scripts/manage.py" status --project "<project-path>"
```

`start`는 실제 Codex 스킬 읽기 점검 후 서비스와 Gateway READY를 확인한다. 이미 같은 설정으로 실행 중이면 서비스를 재사용한다. `doctor --probe`는 파일을 수정하지 않는 실제 모델·스킬 읽기 검사다. RUNNING만으로 온라인을 확정하지 않는다.

같은 채널의 기존 서비스가 있으면 경로와 소유 프로젝트를 확인한다. 사용자가 전환을 요청한 기존 서비스만 종료하고 새 서비스로 연결하며 중복 봇을 띄우지 않는다. 다른 프로젝트 서비스를 임의로 종료하지 않는다. 다른 머신에 있는 서비스는 로컬 검사로 알아낼 수 없으므로 같은 채널을 중복 배정하지 않는다.

실제 수신 확인이 필요하면 사용자에게 해당 채널에 테스트 메시지를 보내도록 안내하고 운영 로그의 수신·답장 기록을 확인한다. 코드 구현까지 확인하는 경우 선택 프로젝트의 기존 작업을 보존하고 범위가 명확한 검증용 파일로 확인한다. 실행하지 않은 검증을 성공으로 보고하지 않는다.

완료 시 프로젝트, 사용자 범위, 설치 버전, 실행 상태, 확인한 검증과 남은 사용자 행동을 짧게 알려준다. 실패 시 준비된 파일·상태를 보존하고 [문제 해결](../../references/troubleshooting.md)의 진단 절차를 적용한다. 임시 클라우드 머신이 종료돼도 서비스가 유지된다고 보장하지 않는다.
